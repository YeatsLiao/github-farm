---

## 2. 核心功能

### 2.1 贡献数据 → 农场元素映射

| GitHub 数据 | 农场元素 | 映射规则 |
|---|---|---|
| 周贡献量（排序分列） | 作物生长阶段 | 52 周按总量升序排列，低贡献→左列种子，高贡献→右列丰收，5 阶段渐变 |
| 连续提交天数 | 稻草人 | ≥ 30 天解锁，放在农田边缘 |
| 编程语言分布 | 树木种类 | 每种 Top 语言一棵树，最多 5 棵 |
| PR 合并数 | 动物出现 | 每 8 个 PR 一只动物，最多 5 只 |
| Issue 参与数 | 花朵装饰 | 每 6 个 Issue 一个装饰，最多 4 个 |

### 2.2 作物生长阶段

| 阶段 | 精灵 | 渲染尺寸 | 视觉描述 |
|------|------|---------|---------|
| 0 - 种子 | r1c1 | 30×20 | 很小的种子 |
| 1 - 嫩芽 | r1c2 | 40×35 | 小绿苗 |
| 2 - 成长 | r1c3 | 55×55 | 中等植物 |
| 3 - 高秆 | r1c4 | 65×80 | 玉米状高植物 |
| 4 - 丰收 | r1c5 | 70×100 | 金色麦子 |

### 2.3 百分位自适应阈值

根据用户数据分布自动确定 5 阶段分界：
- 10% 分位 → 种子/嫩芽边界
- 25% 分位 → 嫩芽/成长边界
- 45% 分位 → 成长/高秆边界
- 65% 分位 → 高秆/丰收边界

确保无论贡献多少，5 阶段都能均匀分布。

### 2.4 输出格式

- **PNG**：Canvas 像素风渲染，1216×832，用于分享和预览
- **SVG**：计划中，可嵌入 GitHub Profile README

### 2.5 使用方式

1. **本地开发**：`npm run dev` 启动开发服务器（localhost:3000），配置 `GITHUB_TOKEN` 使用真实数据
2. **CLI 生成**：`npm run build` 生成 PNG
3. **GitHub Action**（计划中）：自动每日更新

## 3. 用户场景

### 场景 1：开发者展示个人主页
- 用户在 GitHub Profile README 中嵌入农场图
- 访客看到一座生动的像素农场，直观了解贡献活跃度

### 场景 2：年度总结
- 年底生成年度农场全景图
- 左列种子→右列丰收，直观展示全年贡献分布

### 场景 3：团队贡献可视化
- 团队仓库展示团队整体贡献的农场

## 4. 非功能需求

| 需求 | 指标 |

## 6. 竞品分析

| 工具 | 风格 | 差异点 |
|------|------|--------|
| kodama | 日式盆栽 SVG | 我们做农场，更丰富的场景元素 |
| github-contributions-chart | 热力图变体 | 我们做场景化，不只是图表 |
| pixel-profile | 像素资料卡 | 我们做完整农场场景 |
| isometric-contributions | 3D 等距像素 | 我们做 2D 像素农场 |

## 7. 技术选型

- **运行时**：Node.js >= 18（ES Module）
- **渲染**：Canvas（npm `canvas`），像素风 PNG 输出
- **数据源**：GitHub GraphQL API
- **自动化**：GitHub Actions（计划中）
- **素材**：AI 生成像素风精灵图 + 手动调整
- **预览**：内置 HTTP 开发服务器（dev-server.mjs）
