# 06 - 开发决策与踩坑记录

> 开发过程中的关键决策和遇到的坑

## 关键决策

### 决策 1：SVG vs Canvas

| 方案 | 优点 | 缺点 |
|------|------|------|
| SVG | 矢量、无依赖、可嵌入 Markdown | 复杂动画较难 |
| Canvas | 动画灵活 | 需要 node-canvas 依赖、非矢量 |

**选择**：SVG。理由：GitHub README 嵌入场景下，矢量格式无分辨率问题，且纯字符串模板无需外部依赖。

### 决策 2：AI 素材 vs 手绘

**选择**：先用 AI 生成快速原型。理由：降低启动成本，后续可找设计师优化或接受社区贡献。

### 决策 3：ES Module vs CommonJS

**选择**：ES Module。理由：Node.js 18+ 原生支持，与浏览器端代码兼容，现代化标准。

### 决策 4：真实素材 vs 代码绘制

**背景**：最初用 Canvas 代码绘制像素风，效果粗糙。
**选择**：AI 生成真实像素风素材 + SVG 渲染引擎只做排列组合。
**教训**：代码绘制的像素风永远无法匹配手绘/AI 素材的质感。

## 踩坑记录

### Bug 1：Unicode 减号 vs ASCII 减号

**现象**：JavaScript 数组中使用 Unicode 减号 `−` (U+2212) 导致语法错误。
**修复**：替换为 ASCII 连字符 `-` (U+002D)。

### Bug 2：PowerShell 变量插值

**现象**：用 `@"..."@` 写 JS 文件时，`$username`、`$token` 被 PowerShell 解释为变量。
**修复**：改用单引号 here-string `@'...'@`，不解释任何特殊字符。

### Bug 3：ES Module vs CommonJS

**现象**：`package.json` 有 `"type": "module"`，导致 `require()` 不可用。
**修复**：辅助脚本使用 `.cjs` 扩展名。

### Bug 4：themes/stardew.js 多处语法错误

**现象**：base64 编码导致文件内容损坏。
- 冬季 grass 颜色缺少闭合引号
- barn 的 minStreak 使用了 `*` 而非 `:`
- C# 颜色值 `#1N8yCF` 应为 `#1786CF`

**修复**：逐个用 PowerShell 正则替换修复。
**教训**：base64 编码中文内容容易出错，优先用 here-string。

### Bug 5：farm-layout.js 变量名拼写错误

**现象**：`buildScene()` 中 `farmData.totalPPs` 应为 `farmData.totalPRs`。
**影响**：动物元素全部缺失（5 个动物不显示）。
**修复**：修正拼写。

### Bug 6：renderer.js 重复 export

**现象**：函数已用 `export function` 声明，底部又有 `export { ... }` 导致 Duplicate export 错误。
**修复**：删除底部的重复 export 语句。

### Bug 7：base64 编码中文乱码

**现象**：用 base64 写入 renderer.js 后，中文注释全部乱码。
**修复**：改用 PowerShell 单引号 here-string `@'...'@` 直接写入。
**教训**：base64 适合纯 ASCII 内容，中文内容用 here-string 更可靠。

---

## 工具链总结

| 场景 | 推荐方案 |
|------|----------|
| 写含 `$` 的 JS 文件 | PowerShell `@'...'@` here-string |
| 写纯 ASCII 的 JS 文件 | base64 编码 |
| 修改已有文件 | SearchReplace 工具 |
| 创建新文件 | Write 工具（workspace 内）/ here-string（workspace 外） |
