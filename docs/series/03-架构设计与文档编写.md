# 03 - 架构设计与文档编写

> 先写文档再写代码，确保开发方向清晰

## 文档先行原则

按照项目开发流程要求，在编写任何核心代码之前，先完成以下文档：

1. **PRD（产品需求文档）** - 定义做什么
2. **架构设计文档** - 定义怎么做
3. **开发记录** - 记录过程

## 架构设计

### 三层架构

```
用户入口层（CLI / GitHub Action / Dev Server）
        |
核心逻辑层（fetcher → layout → renderer）
        |
数据/资源层（GitHub API / 素材文件 / 输出目录）
```

### 5 个核心模块

| 模块 | 文件 | 职责 |
|------|------|------|
| 数据获取 | fetcher.js | GitHub GraphQL API → FarmData |
| 主题配置 | themes/stardew.js | 配色/精灵/布局参数 |
| 布局算法 | farm-layout.js | FarmData → SceneElement[] |
| SVG 渲染 | renderer.js | SceneElement[] → SVG String |
| 主入口 | index.js | CLI + 可编程 API |

### 数据流

```
GitHub GraphQL API → fetcher.js → FarmData
                              → themes/stardew.js → ThemeConfig
                              → farm-layout.js → SceneElement[]
                              → renderer.js → SVG String
                              → dist/farm.svg
```

## 扩展点设计

架构预留了 3 个扩展方向：

1. **新主题**：在 themes/ 下新建文件（如 city.js、ocean.js）
2. **新输出格式**：添加 canvas.js 或 png.js 渲染器
3. **新数据源**：添加 local.js 或 gitlab.js 数据获取器
