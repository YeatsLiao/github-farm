# GitHub Farm 升级计划

当前版本包含三种农场的成长路线、地点探索、活动动画和溪边果园五阶段对照。日夜、天气和节日装饰留作后续主题。

## 目标

让任意公开仓库的 Stars 生成一座紧凑、可辨认、能逛的像素农场。延续已选定的温暖像素风。0 Stars 有完整院子和可用的菜地或水边，高 Star 时逐步长出功能区和生活细节。同一个仓库改名或涨 Star 时，小屋、池岸和主路的位置保持稳定。

## 第一轮 · 把溪边果园做成完整样机

用同一个仓库 ID 渲染 **0、5、25、100、300 Stars**。对照图用固定视角，页面允许在同一个地点观察变化。

- **0 Stars** 有小屋、果树幼苗、一块菜地和通往水边的小路。院子用现有花草、箱子和围栏做出使用痕迹。
- **5 Stars** 第一棵幼树结果，果树在原位更换阶段。
- **25 Stars** 院子增加收获台和空篮，门口到果树之间留出行走空间。
- **100 Stars** 添置果酱棚，用小路连接果树、收获台和棚门。
- **300 Stars** 拓出第二排果树和水边小码头，新区域带上入口与用途。

先完成两项网页交互。点击菜地、池塘或建筑能看到用途与解锁条件。拖动成长滑杆能回看此前档位，向前看时显示「预览」以及仍需多少 Stars。真实卡片与预览共用绘制规则，查看或试玩不会改仓库统计。

**交付**包括[果园五阶段对照](https://yeatsliao.github.io/github-farm/orchard-growth.png)和[可操作的果园](https://yeatsliao.github.io/github-farm/?repo=octocat%2Fgit-consortium)。验收时检查 0 Stars 画面是否饱满、各阶段是否在 README 宽度下容易区分、原有地标是否原位、路径是否连接，以及触屏与键盘能否操作。

## 第二轮 · 扩展到三种农场

把果园验证过的规则扩展到另外两种布局。种子决定地形与主业，也能在合法位置中选择树种、作物和小道具。农场里的地物逐段成长，扩建前检查入口和连通性。

- **庭院菜园**从育苗、分垄种植发展到晾晒和储存。
- **溪边果园**从幼树、收果发展到果酱棚和临水码头。
- **谷仓牧场**从鸡舍发展到围栏牧场、谷仓和饲料区。

保留低 Star 的密集档位。100 至 5,000 Stars 每 100 Stars 至少有一处容易看见的变化。常规档位可以是作物成熟、果树结果或围栏延伸。较大节点解锁新的用途，5,000 Stars 保留风车。验收时对比同一农场的不同档、不同仓库的同一档，并检查 5,000 Stars 以上的卡片显示。

## 第三轮 · 增加农场的日常

果园活动是「树旁采果 → 搬到收获台 → 回去取下一篮」。路线跟随步道，解锁码头后可以看到鸭子游过水面。菜园和牧场分别展示种植收获和喂养路线。

网页支持暂停活动，并遵循系统的减少动态效果设置。README 由 Actions 定时发布 PNG，复用网页的场景、统计与卡片渲染规则。

## 素材与代码落点

- 现有图集继续用于建筑和自然物。果酱棚复用小屋形状并配专用标牌，收获篮、收获台、饲料箱等用少量原生像素绘制。
- 可提供 2–3 张参考截图，分别看紧凑全景、果园细节和生活动作。推荐可用素材时附原始链接、作者和使用条件。[素材规范](ASSETS.md)
- 原稿放在 `assets/source/`，图集与清单放在 `assets/runtime/`，生成的对照图放在 `dist/`。
- 成长和布局规则放在 `src/farm/`，画图放在 `src/render/`，网页交互从 `scripts/pages.js` 接入。[项目结构](ARCHITECTURE.md)

实现后运行 `npm test` 和 Pages 构建，并在浏览器里用一个低 Star 仓库和一个 100 Stars 以上的真实仓库各走一遍输入、生成、预览与下载流程。
