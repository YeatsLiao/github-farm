# GitHub Farm — 产品需求与美术方案

> 更新：2026-10-24。当前交付为 Spring Preview 本地动态样板，不是已经上线的公共服务。

## 1. 产品目标

让用户输入 GitHub 用户名，或在后续版本授权账号，即可拥有一座随贡献变化的像素农场。

核心体验不是把热力图换成另一种图表，而是「贡献有生长，农场有生命」。美术质量与动态表现优先于登录、复杂养成和主题数量。

- 仓库：https://github.com/YeatsLiao/github-farm
- 当前输出：浏览器 Canvas 动画、PNG。
- 后续输出：README 短循环 GIF、公共图片地址；SVG 作为可选项。
- 代码许可证：MIT；素材来源需与代码说明分开记录。

## 2. 视觉基准与素材策略

### 2.1 不变的目标

[原始概念预览](images/farm-concept.png)是审美基准，README 中的概念图不替换、不把样板截图冒充原始目标。

保留红色木谷仓、草地围栏、棕色农田、左侧幼苗与右侧金色麦田的视觉关系。用户在首批24种验收时指出浮岛边界、物件比例与摆放不合理，明确允许地图铺满；当前改为地面铺满画布，不再强制蓝天留白和浮岛断面。保持温暖、有细节的像素田园感，不改成极简几何图、统计卡或菱形等距城市。

[原始精灵参考](../assets/scenes/reference-spritesheet.png)保留作历史参考，不再作为新版运行时资产。

### 2.2 已确认的问题

- 原素材由抠图得到，独立精灵与概念背景在描边、细节密度、比例和透视上不完全一致。
- 背景中固定的人物、小鸡和云无法独立做动画。
- 单纯换渲染库、裁边或拉伸尺寸，无法解决整体画风不统一。
- 铺满版仍有直线布局、重复草纹和素材贴纸感；边缘融合完成后，用户反馈整体改善，但进一步要求温馨、合理的区域组织，不能继续全画布散点摆放或只微调坐标。逻辑测试通过不代表审美已验收。

### 2.3 当前执行路线

采用「参考图定风格 → AI 辅助新绘制 → 透明化与边缘清理 → 场景合成验收 → 动画调校」。不是为每次访问实时生成整张 AI 农场。

- 新资产位于 `assets/spring/`，与旧 `assets/sprites/` 分离；当前24种素材完全不读取旧抠图。`src/renderer.js` 的历史 API 和 `python/renderer.py` 仍引用旧目录，本轮不删除这些历史依赖，避免破坏未迁移的 Python 实验。
- 当前整体构图重建为紧凑「林间农家院」：中央住宅、左侧畜牧院、右下两块错落农田、左下池塘花园、右上林地。采用「划区域 → 定建筑和入口 → 连道路 → 摆附属物」，底图、物件、活动和轻布置共用规则，不全画布随机撒点。
- 恢复明亮草绿和暖黄土路，使用木栏、门廊花朵与窗灯点缀，保留非重复地面和已认可的边缘融合，不继续整体降饱和或模糊。两田以小径分隔，容量30＋23周；位置重排但周日期、贡献总量与排序规则不变。
- 场景比例保留：树高124／132、小屋142、谷仓168、农夫36、小鸡16逻辑像素。原整幅上沿围栏改为谷仓小院围栏；所有物件完整轮廓仍须留在地图内，不能靠裁切隐藏越界。
- 首批24种对象已入库，共51个对象画面／生长阶段／动作帧，加2朵环境云，总计53个精灵。三个作物各有五阶段；人物、猫、鸡、鱼和吉祥物各有四张基础动作帧。
- 图集保留色键源稿和透明成品；24种对象在轮廓带清理紫／青残色、以邻近主体颜色减弱过黑描边，最外圈向透明过渡。植物底座另外渐隐，主体内部不模糊，不烘焙固定草地色；屋脚、树根和池岸补充位置相关的接地层，移动后不残留阴影。使用透明贴图本身不是问题，风格、落地位置和边缘质量才是验收重点。
- 图集仍属于 AI 辅助初稿，精细动作一致性与少量边缘色溢仍可继续人工打磨。
- [当前实际合成样张](images/spring-preview.png)与目标概念图分开保存；[首批24种联系表](../assets/spring/catalog24.png)用于逐项验收。
- 沿用已认可的新麦子、小鸡、两种树、雏菊和稻草人共6种对象；新增18种，与「淘汰旧抠图」不冲突，不重复生成已认可的资产来凑数量。

### 2.4 林间农家院分区（已确认并实现）

| 区域 | 组成与约束 |
|---|---|
| 住宅小院 | 小屋与门廊为中心，短路接路口；花、灯、猫围绕门廊，门前通道留空 |
| 畜牧院 | 谷仓与前栏、侧栏形成院落，东侧留门；小鸡只在院内走停和啄食 |
| 种植区 | 两块田紧邻住宅，分别容纳30周与23周；水井靠入口，稻草人与向日葵在田边，装饰不遮住周槽点选范围 |
| 池塘花园 | 池塘、芦苇、花草、路灯与芽芽成组；岸边小径连到院落主路，鱼限于水内 |
| 林地角落 | 树木成簇、树冠收在林地上方，矿石靠树根成组；不跨区独立散放 |

各区规定允许素材、脚底范围、入口与相关活动约束，区域用错落矩形并集表达。花草在预留位置内有不超过4像素的确定性变化，只有通过布置规则才采用。常驻环境与区域结构不依赖贡献高低；不新增素材种类或经营玩法。

### 2.5 后续可选工具

- [PixelLab](https://www.pixellab.ai/)：试验参考风格素材、角色动作和像素资产生成。
- Aseprite：清理透明边缘、统一调色板、锚点与动作帧。
- [Sunnyside World](https://danieldiggle.itch.io/sunnyside)：如果以后接受调整画风，可评估成套素材；不能不检查再分发许可就提交资产。
- 若投入人工美术预算，优先统一关键作物与鸡的动画帧，而不是立即重画所有内容。

未购买素材或接入付费 API。首批源稿由项目现有图像生成能力产出；边缘融合轮次经用户选择安装并启用社区 `pixel-art-sprites` 指南，使用本地加工与渲染，没有重新生成对象或安装外部美术服务。

## 3. Spring Preview 功能范围

### 3.1 已实现

- 输入用户名，生成确定性演示农场；同名、同档位不会刷新成完全不同的数据。
- 低／中／高三档贡献演示，并明确标记不是账号真实统计。
- 配置服务端 `GITHUB_TOKEN` 后，页面可手动切换 GitHub 真实数据。
- 麦子、胡萝卜、南瓜轻摆，小鸡在畜牧围栏内以错峰短路线行走／停留／啄食；蝴蝶围绕门廊与池岸花朵，暮色萤火集中池边。两朵云素材保留但不绘制在地面。
- 农夫沿门廊—路口—田侧预设通路往返，猫在门廊眨眼／伸展／睡觉，锦鲤在池内游动，芽芽在池岸眨眼／挥手；不是全方向自由寻路角色。
- 24种素材册可点选查看。轻布置支持移动现有花草、树、路灯、水井、稻草人和矿物，4像素吸附、方向键微调、占地检查、最多20步撤销与恢复默认。
- 轻布置仅保留在本次网页预览，成功切换账号／档位时重置，可通过 PNG 留存。建筑、池塘、围栏、铺路石及角色目前固定，不支持新增任意数量物件。
- 晴昼／暮色切换；暮色窗灯与萤火光点。暮色是光照预设，不等同于真实昼夜天文模拟。
- 点击作物或用左右方向键选中地块，显示日期、贡献量和阶段。
- 暂停／继续、减少动态效果偏好、页面隐藏时停止绘制。
- 导出当前时刻 PNG；CLI 与网页使用同一份场景及绘制规则。

### 3.2 未实现，不应对外承诺

- OAuth 登录、个人配置保存、私有贡献授权策略。
- 公共在线托管、稳定图片域名、CDN 缓存与运营级限流。
- GIF 编码和 README 动态图片自动更新。
- 完整四季素材、角色自由寻路、可交互经营游戏。
- 作物跨阶段成长动画、数据更新时的平滑位置过渡与新动物入场。
- 对任意用户名实时生成全新美术、自然语言主题配置。

## 4. 数据映射与真实性

### 4.1 作物

每周对应一个作物簇，按周贡献总量升序分配到可种植区域。槽位避让谷仓与道路，最多容纳 53 周。排序是观赏模式，不是时间轴；每周的起止日期和原始贡献数始终保留。

| 周贡献量 | 当前阶段 |
|---|---|
| 0 | 休耕，不伪造作物 |
| 1–7 | 种子 |
| 8–21 | 嫩芽 |
| 22–49 | 成长 |
| 50–99 | 茂盛 |
| ≥100 | 丰收 |

这些是样板阶段的可调阈值。暂不沿用 v8 的每个账号分别计算百分位，避免少贡献和多贡献最终看起来一样丰收。低贡献农场通过环境、小鸡与细节保持美感，不靠虚增贡献。作物种类按固定槽位混种（麦子为主，穿插胡萝卜和南瓜），本轮不将不同物种绑定到新的 GitHub 指标。

### 4.2 场景点缀

| 数据／元素 | 当前规则 | 口径说明 |
|---|---|---|
| 常驻小鸡 | 2 只 | 环境角色，不代表 PR |
| PR | 每 8 个额外增加 1 只鸡，最多额外 3 只 | 当前 API 为用户累计 PR 总数，非仅合并 PR |
| 语言 | 最多 3 棵独立树 | 基于最多 100 个自有仓库的主语言计数近似值 |
| Issue | 每 6 个增加一簇花，最多 4 簇 | 当前 API 为用户创建的 Issue 累计数，非讨论参与次数 |
| 连续贡献 | 当前或历史连续 ≥30 天显示稻草人 | 沿用现有连续贡献统计 |
| 云、蝴蝶、常驻树与花草、建筑、池塘、鱼、农夫、猫、芽芽、矿物 | 环境资产 | 不编码额外贡献；语言树与 Issue 花在此基础上额外添加 |

周贡献日历与 PR／Issue 累计数的时间范围不同，后续可增加明确的时间过滤。不得继续把当前 PR 总数标注成「已合并 PR」、把创建 Issue 数标注成「参与讨论数」。

## 5. 活灵活现的验收要求

- 静止截图仍然好看：整体风格、像素密度、光照与落地感一致，不能依赖动画掩盖贴纸感。
- 柔化针对轮廓和接地，不对整张精灵或画布加模糊；植物细茎、种子、角色脚部与紫水晶主体须保留。晴昼、暮色及移动后都要检查边缘与底座，不能只在单一底色上看起来干净。
- 小鸡走几步会停、会啄食，个体动作错峰；完整外观始终留在畜牧院活动范围，不能穿过围栏、谷仓或装饰，不声称具备全地图寻路。
- 作物根部固定，叶片轻摆；不是整张贴图上下漂浮。
- 池塘和石径先绘制于地面层，其余物件与作物按当前落脚点由远及近绘制；近处树木可自然遮挡后方物件，平铺石径不能盖住人物。
- 贡献为零、较少、中等和较多时都不越界；53 周也能显示。
- 暂停后画面稳定；减弱动态偏好默认暂停，仍能查看和导出。
- 用户审美确认是独立验收项，自动化测试通过不代表已达到概念图同等美术质量。

## 6. 产品入口与 AI 边界

目标流程：输入用户名 → 查看农场 → 调整外观 → 保存图片／复制 README 嵌入代码。后续授权用于保存配置及权限允许的个人数据，不阻塞第一版公开数据体验。

当前本地网页默认演示，真实 GitHub 数据要在服务端配置 Token。无需访客登录不等于后端无需认证；Token 不进入浏览器，不出现在 URL 或导出图中。

AI 当前只参与素材制作。以后可将「秋天、黄昏、多一些花」解析为白名单主题配置，但贡献数量、布局约束与素材选择仍由程序校验。模型不控制实时小鸡行为，也不负责算贡献数。

## 7. 三阶段实施顺序（用户已确认）

| 顺序 | 阶段 | 范围与边界 |
|---|---|---|
| 1 | 农场美术与操作 | 当前唯一推进阶段：新素材库、场景分层、布局、动画，以及农场内点选等操作；具体编辑操作范围继续讨论 |
| 2 | 整个网站显示与交互 | 第一阶段通过后，再统一网页布局、导航、响应式、配置面板和导出体验 |
| 3 | 与 GitHub 关联 | 最后完善真实贡献口径、授权、配置保存、公共图片服务与 README／Action 自动更新 |

现有网页、演示 API 和真实数据原型可继续使用，但不因为已经存在就提前扩展第二、第三阶段。用户已肯定第一版视觉效果，并认可新紫底图集的方向；这不等于全部素材和操作已经验收。

### 7.2 美术生产约束

- 沿用用户认可的新紫底图集的材质、描边与田园配色，不回用旧抠图，也不重新生成已经认可的基础资产来凑数量。
- 每批聚焦同一类别的 4–8 个新对象；人物和动物动作单独出图集，采用已确认的标准帧作为参考。
- 先确定农夫、鸡、树、房屋的场景尺寸比例，再生成；建筑使用较大画幅，不挤进和花草一样大小的格子。
- 背景中现有谷仓、围栏与树必须移除或拆层后，才能允许这些对象单独摆放；避免出现底图建筑与新建筑重影。
- 物体图、背包图标、动画帧分别管理；不能直接把收集品图标放大当场景素材。
- 色键不能与对象颜色冲突。紫水晶、紫花等紫色主体使用另一种不冲突的色键或真实透明背景，不能直接套用当前紫红去底脚本。
- 同屏不强制摆满64种。当前已批准并实现住宅、畜牧、种植、池塘花园、林地五区，保留道路、草地和视觉留白；64种扩充仍需另行批准。
- 新类型先通过单张与合成验收，再扩生长阶段和动作，避免风格不统一时批量返工。

### 7.3 首批农场内操作

已接入「观赏＋轻布置」：点选查看、移动现有可移动物件、4像素吸附、方向键微调、建筑与池塘占地检查、撤销和恢复默认。进入布置模式后先选中物件，再点击空草地放置；Esc取消选择。当前不支持拖动建筑／池塘或从素材册无限增添对象。

布置仅修改对象坐标，不修改贡献数、日期、地块和鸡的统计来源。物件只能在所属区域内调整，详情与错误提示显示区域名称。脚底须符合允许素材及区域形状，不能覆盖已有物件、耕地、道路、门口、岸边小径或鸡活动区；完整外观不能越地图边界或遮住作物根部点选区，树冠另不能遮住房屋和农田。无合法位置时保持原位。区域采用矩形并集，物件仍为矩形占地检查，不是逐像素碰撞或自由全地图编辑器。

人物移动、浇水、收割、钓鱼、背包与矿物收集属于进一步玩法选择，需要另行讨论，不因生成了这些素材就自动纳入实现范围。
